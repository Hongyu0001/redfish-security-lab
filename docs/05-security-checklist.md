# 从靶场到真实业务：给非渗透岗的一份安全巡检清单

> 家庭网络安全实验室系列第五篇。十关打通之后，真正的收获不是会打，而是知道该防哪。

## 先泼一盆冷水

DVWA 里的攻击都很“漂亮”：一个单引号读出一整张表、一个 GET 改掉密码、一个上传拿到执行权限。真实业务里很少这么戏剧化，但根因一模一样，只是藏在日常操作里——口令用生日、后台账号共用、日志没人看、备份放在同一块硬盘。

这份清单不是给渗透工程师的，是给店里、办公室里管电脑和系统的人，按季度自查用的。

## 一、账号与权限

**查什么**：有多少个后台账号，各自什么权限，谁还在用。

**怎么查**：列出所有管理后台、系统、云服务的账号清单；对照现在的人员名单，划掉离职和转岗的。

**算有问题**：一个账号多人用（出事查不到是谁）、权限只增不减、离职三个月账号还活着。

**最小动作**：管理员账号一人一个、实名；只给岗位需要的权限；离职当天停权。

## 二、口令

**查什么**：口令是否弱、是否重复、是否明文存放。

**怎么查**：抽几个常用系统，问当事人口令是不是生日、手机号、姓名拼音；检查有没有把口令存在便签、聊天记录、Excel 里。

**算有问题**：同一个口令用在多个系统（一个泄露全泄）、口令含个人信息、明文写在文件里。

**最小动作**：重要系统开二次验证；口令至少一条“长短语式”的（四个不相关词组合，比复杂短串更难破）；管理层口令不共用。

## 三、日志

**查什么**：登录、关键操作有没有记录，记录留多久，出事能不能翻出来。

**怎么查**：故意输错一次密码，看系统有没有记；查一次修改密码或删除记录，看有没有操作人。

**算有问题**：只有“成功”没有“失败”记录、日志只留三天、操作记录没有操作人。

**最小动作**：至少保留 90 天；关键操作带操作人；日志单独存一份，别和业务数据放一起。

（这部分正好对应第三篇的 Wazuh：不是非要上 SOC，但要知道日志在哪、能不能看。）

## 四、备份

**查什么**：备份在不在、能不能恢复、多久一次。

**怎么查**：随便挑一个文件，尝试从备份恢复一次。这是唯一可靠的验证。

**算有问题**：从没恢复演练过、备份和原数据在同一块盘、备份只有一份、没人知道备份在哪。

**最小动作**：3-2-1 原则（三份、两种介质、一份异地）；每季度恢复演练一次；备份位置写进交接文档。

## 五、组件与更新

**查什么**：系统、浏览器、办公软件、业务系统版本。

**怎么查**：看更新记录；业务系统问供应商最近一次安全补丁是什么时候。

**算有问题**：业务系统三年没更新、服务器操作系统早过了支持期、补丁靠“出问题再说”。

**最小动作**：能自动更新的开自动；不能更新的（老业务系统）做网络隔离，别让它直接暴露在公网。

## 六、网络边界

**查什么**：哪些设备对公网开放，哪些端口开着。

**怎么查**：让懂的人从外网扫一遍自家公网 IP；内部检查路由器有没有开端口映射、有没有默认口令。

**算有问题**：摄像头、打印服务器、NAS 默认口令暴露在公网；远程桌面直接开在公网。

**最小动作**：默认口令全改；远程访问走 VPN 或跳板，别裸奔。

## 怎么用这份清单

1. 每季度一次，两个人一起做——一个人查，一个人记。
2. 每条只记“符合 / 不符合 / 暂无法核查”，别追求完美打分。
3. 不符合的写成一条整改项，指定人和期限，下季度回访。
4. 清单本身要更新：业务变了，清单跟着变。

## 结语

十关靶场教会我最有用的一句话：**漏洞几乎都不是“技术难题”，而是“没人负责”**。参数化查询、编码输出、白名单、二次验证，这些方案十年前就有，缺的只是有人定期看一眼、有人对结果负责。

安全不是买一个产品，是一套有人执行的习惯。
